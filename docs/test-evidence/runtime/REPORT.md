Evidence is stored in each `artifacts/runtime/<run-id>/result.json`, with stage verdicts, exact argv, exit codes, stdout/stderr hashes, source/tool/worker hashes and artifacts. [API acceptance](api-acceptance.json) and [JUnit](api-acceptance.xml) record **16 baseline/negative workflow cases across eight profiles**. The Ibex invalid-ELF control checks loader rejection before CPU execution; other cases run native simulations. Earlier failed attempts are retained in attempt history and raw artifacts.

Wellen reads actual VCD/FST through the runtime API, uses stable signal IDs scoped by run/artifact, integer tick windows and cursor values. [Reader semantic checks](wellen-reader-checks.json) cover precision beyond JS Number, X/Z, missing sample, bounded transitions and unknown-ID rejection. [Process controls](process-controls.json) exercise real descendant cancellation/timeout. These fixtures are not CPU simulation tests.

Default UI end tick is `auto`, fitted to actual trace changes/clock edges rather than assuming VCD and FST share a tick magnitude. Default signals avoid repeated short-name clock aliases. This was checked after visual inspection found an overly wide initial FST viewport; manual integer windows remain supported.

Limits: reference profiles only; no full filesystem/network sandbox or team RBAC; external OS/toolchain/firmware redistribution review remains open. SystemC standalone uses a synthetic initiator; SystemC/Verilator drives actual RTL but is not a gem5 CPU hybrid. Waveform/source mapping is unavailable. gem5 is an architecture CPU model, not vendor RTL. ROHD integration and arbitrary composed SoC execution remain open. [ADR-008](../../decisions/ADR-008-engine-runtime.md), [architecture](../../architecture/RUNTIME_PIPELINES.md), [license inventory](license-inventory.json).

The gem5/SystemC profile uses gem5's internal SystemC implementation, not the external `util/tlm` demonstration or external SystemC library ABI. Its monitor decoder knows traffic type/time/order, not payload addresses/data; those fields are null. Derived pairing assumes one outstanding TimingSimpleCPU request. This is not full M8 gem5 → SystemC → Verilated RTL acceptance.

Observed issues resolved during integration: NTFS Git CRLF/ownership checks use explicit local options; source staging copies bytes without chmod/copystat. Verilator uses `--timing -UVERILATOR` to retain the upstream SV timing testbench rather than its older C++ branch. The upstream Ibex loader returns zero for invalid ELF, so success/rejection requires output/trace/error oracles. gem5 requires `--build-info`, not `--version`; its SimObject System parameters resolve through Parent.any to avoid ownership cycles. Some TlmBridge logs omit newlines; the decoder recognizes explicit timestamp prefixes. Earlier acceptance report serialization had a variable-shadowing error after all jobs completed; records were recovered from persisted API runs and waveform endpoints rechecked without fabricating or rerunning their results.
